# 配图引擎选型需求（Text-to-Image Engine Requirements）

> **版本** v1.0 ｜ **日期** 2026-10-24 ｜ **状态**：待评审
> **目标**：为「今日新闻简报」的自动配图选一个**开源、可自建、长期稳定**的文生图引擎，
> 升级/替换现有 `/api/ai-image` 通道。
> **数据来源**：§2 为**本机实测**；§9 候选数据为 **2026-10-24 通过 GitHub API 实测抓取**
> （stars / 许可证 / 最后提交 / release），不是凭印象写的。显存与速度为公开资料，标注了出处。

---

## 1. 背景与目标场景

### 1.1 现有配图链路

```
源站正文图 → 新闻图库复用 → 代码生成 SVG（/api/code-image）→ AI 升级（/api/ai-image，可选）
```

### 1.2 为什么"未达标准"（先把问题说准）

| 现象 | 根因 |
|---|---|
| 画面与新闻只到"板块级"契合 | 代码生成的是**抽象几何母题**（电路/轨道/柱状/波纹…），由"分类 + 关键词 + 标题指纹"决定，画不出"这条新闻的具体画面" |
| 清晰度上限低 | 本质是矢量图，放大到 1200² 仍是平的，缺少质感、光影、细节层次 |
| 几乎看不到 AI 图 | `/api/ai-image` 依赖云端密钥，本机实测 **`BUDDY_CLOUD_TOKEN` 未配置**（2026-10-23 实测），AI 升级通道一直没生效 |

结论要承认：现在的"100% 有图"是靠 **SVG 保底**撑住的，它解决了"有没有"，
没解决"好不好"。本次选型解决的是后者。

### 1.3 目标场景（后面所有指标都由它推导）

- **输入量**：每日 7 个权威 RSS 源 → 15~25 条中文新闻，4 个板块（政治 / 科技 / 财经 / 生活）
- **用途**：列表缩略图（方图）+ 沉浸浏览上半屏封面（3:4 竖裁切）
- **时效**：每天生成一次，**允许后台跑分钟级**，但必须 **100% 有图**（缺图要有保底）
- **无人值守**：本机常驻，不需人工干预；不得把新闻内容回传第三方

## 2. 硬约束（本机实测，2026-10-24）

| 项 | 实测值 | 对选型的影响 |
|---|---|---|
| 操作系统 | Windows 10 专业版 19045 | 优先选有 Windows 支持的项目 |
| CPU | Intel i7-10510U **4 核 8 线程**（低压笔记本） | CPU 路线会比桌面 i7 慢 2~4 倍 |
| GPU | Intel UHD(1GB) + **NVIDIA MX250 2GB**（驱动 457.30） | **决定性约束** |
| 内存 | **7.8 GB** | CPU 路线也要控内存 |
| 磁盘 | C 盘可用 68.5 GB，**D 盘可用 327.6 GB** | 模型放 D 盘 |
| Python | 3.13.14（**torch / diffusers 均未装**） | 需独立 venv（3.10/3.11）或选无 torch 依赖的实现 |

**由此得出的三条硬结论（先说清楚，避免选一个本机跑不起来的）：**

1. 显存 2 GB → SDXL（≥6 GB）、FLUX.1-schnell（12 GB）、Qwen-Image（FP8 约 16 GB）
   **本机全部不可行**；
2. 内存 7.8 GB → CPU 路线进程 RSS 需 ≤4 GB；
3. Python 3.13 → 官方 torch wheel 不支持，要么建 3.10/3.11 的 venv，
   要么选**不依赖 torch** 的实现（如 `stable-diffusion.cpp`）。

> 因此本文档把选型分成**两档**：
> **本机档**（小模型 / CPU / 2GB 极限优化，零成本、离线）与
> **质量档**（需 ≥12 GB 显存的机器或云 GPU）。两档门槛都写清楚，按预算选。

## 3. 图像风格与分辨率要求

| 项 | 要求 |
|---|---|
| **输出尺寸** | 正方形 **1200×1200**；须保证 1200×1600（3:4）竖裁切**不切掉主体** |
| **有效分辨率** | 原生 ≥1024² 直接出；若原生 ≤768²，**必须过超分**（Real-ESRGAN 一类）到 1200²，**禁止只做双线性拉伸** |
| **清晰度** | 主体边缘清晰、无糊块 / 过锐 / 网格伪影；不出现重复肢体、畸形手部（负向提示 + 人工抽检） |
| **构图** | 主体居中，四周留白 ≥8%；方图与竖裁切都保主体 |
| **风格** | **新闻配图 / 编辑插画**：写实偏克制的摄影感，或高质量概念插画；低饱和，避免过度艺术化与炫光 |
| **禁止项（硬性）** | 画面内**不得出现任何文字、字母、数字、水印、Logo、边框、角标、图标**；**不得生成可识别的真实人物肖像**（时政新闻尤其重要，改用象征性意象：会场、城市天际线、握手、科技符号、数据可视化元素等） |
| **一致性** | 同一条新闻（同 prompt + 同 seed）重复生成，结果**完全一致**（用于缓存与复现） |
| **文件** | PNG / JPEG / WebP，单张 ≤1.5 MB；24h 缓存；落盘 `assets/images/gen/` |

## 4. 输入描述的形式与长度范围

**前端现在就能提供**（`js/aiImage.js` 的 `extractNewsKeywords` + `js/summarize.js`）：

| 字段 | 形式 | 长度 |
|---|---|---|
| `title` | 中文新闻标题 | ≤ 40 字 |
| `summary` | 正文要点 / RSS 摘要 | ≤ 120 字 |
| `keywords` | 中文关键词数组 | 3~6 个 |
| `category` | 政治 / 科技 / 财经 / 生活 | 枚举 |

**提示词组装规则：**

- 结构：`[主体] , [场景] , [风格] , [构图] , [光线] , [色彩]`
- **长度**：SD 系受 CLIP tokenizer **77 token 硬上限**约束 → 实际正文 **≤75 token**，
  超限按"关键词优先"截断；Qwen-Image / Kolors 等中文模型可直接用中文（≤120 字）
- **负向提示（固定模板）**：
  `text, letters, words, numbers, watermark, logo, signature, frame, border, UI,
  chart, arrow, lowres, blurry, jpeg artifacts, deformed hands, extra limbs,
  realistic human face, portrait of a real person`
- **时政类**：走"象征意象白名单 + 负向提示"双保险，不生成真人肖像、不生成机构标识

## 5. 批量生成与接口调用需求

| 项 | 要求 |
|---|---|
| **批量** | 一次 15~25 个任务；并发 **1~2**（本机）；队列化；同 id / 同指纹直接返回缓存 |
| **接口契约** | **与现有 `/api/ai-image` 保持一致，前端零改动** |
| 请求体 | `{id, category, keywords[], prompt?, title, summary?, seed?, width, height, steps}` |
| 成功响应 | `{ok:true, url, from, meta:{model, steps, seed, elapsed_ms, width, height}}` |
| 失败响应 | `{ok:false, error, message}` → 前端保留 SVG 保底（现状已实现） |
| **异步** | 本机单张可能 10~90 s，需 **提交即返回 job_id + 轮询**；前端现有"先上保底图、好了再替换"机制天然适配 |
| **超时/重试** | 单张 90 s 超时；失败重试 1 次；**连续 3 次失败 → 当天熔断**，不再调用 |
| **复用** | 生成结果写入图库 `library.json` + 质量分，供以后同类新闻复用（已有机制） |
| **可观测** | 每张记录耗时 / 峰值显存（或 RSS）/ 失败原因到日志；沿用 P24 的 stderr 落盘约定 |

## 6. 部署与运行环境

- **形态**：**独立常驻服务**（HTTP API），与 `start-server.ps1` 各自独立进程，互不拖累
- **依赖隔离**：独立 venv（Python **3.10 / 3.11**），或选**无 torch 依赖**的实现
- **本机三条硬件路径**：

| 路径 | 方案 | 预估 |
|---|---|---|
| A. CPU | `openvino`(Apache-2.0) + LCM / SDXS / Turbo：512² 在 i7-12700 上约 0.8~2.5 s（公开基准） | 本机 i7-10510U 预计 **3~10 s**，再超分到 1200² |
| B. MX250 2GB | SD1.5 系 + fp16 + lowvram / Vulkan（`stable-diffusion.cpp`） | **需 PoC 验证是否 OOM** |
| C. 换机 / 云 GPU（≥12GB） | FLUX.1-schnell / Qwen-Image FP8 | 秒级，质量最好 |

- **模型存放**：D 盘（327 GB 可用）；首次下载 2~25 GB，需记录版本与校验值
- **离线**：首次下载后全程离线运行；运行时不得把新闻内容回传第三方
- **守护**：崩溃自动重启；提供 `/health` 健康检查端口

## 10. 筛选依据

### 10.1 硬性门槛（不满足即淘汰）

| 编号 | 门槛 |
|---|---|
| T1 | 许可证 permissive（Apache-2.0 / MIT / BSD），或可书面确认合规 |
| T2 | **近 6 个月有代码提交**，且**近 12 个月有正式发版**（"星数高 ≠ 还活着"） |
| T3 | 可编程调用（HTTP API / CLI / 库），能无人值守批处理 |
| T4 | 显存/内存门槛落在本机档或明确的升级档内 |
| T5 | 支持固定 seed（结果可复现） |

**筛选结果：**

- ❌ **淘汰**：Fooocus（最后正式版停在 2024-08，官方定性 LTS 仅修 bug、明确不支持 FLUX/SD3.5）、
  A1111（2025-02 后无发版）、Kolors（2024-11 后无提交）、PixArt-α（2024-10 后无提交）
- ⚠️ **观察**：DiffSynth-Studio（代码活跃但发版停在 2025-11）、InvokeAI（v7 仍是 alpha，**锁 v6.14.2**）
- ✅ **入围**：ComfyUI（活跃度第一）、stable-diffusion.cpp（本机档唯一现实选项，且无 torch 依赖）、
  InvokeAI / diffusers（许可证与接口最友好）、Qwen-Image / FLUX.1-schnell（质量档，需显存）

### 10.2 加权评分（满分 100）

| 维度 | 权重 | 打分方式（1~5 分） |
|---|---|---|
| **图文契合度** | 30 | 人工盲评"这图像不像是这条新闻的配图" + CLIP-Score |
| **清晰度** | 20 | 1200² 有效分辨率、无伪影、超分质量（可选 BRISQUE/NIQE） |
| **稳定性** | 20 | 200 张连跑的失败率、内存增长、崩溃次数 |
| **许可证合规** | 10 | 许可证类型与留痕完整度 |
| **部署/维护成本** | 10 | 安装步骤数、依赖冲突（尤其 Python 3.13 与 torch） |
| **性能** | 10 | 单张 P50/P95、批量总时长 |

**入围线**：加权 **≥70 分**，且"合规"单项 **≥4 分**；
**一票否决**：非商业许可权重 → 合规项记 0 分。

### 10.3 自动评测流水线（避免拍脑袋）

1. **数据集**：真实 RSS 抽 10 条（4 个板块各 2~3 条），每条出 2 张（不同 seed）
2. **自动指标**：CLIP ViT-L/14 图文相似度 ≥0.26；**OCR 文字检测必须为 0**；
   分辨率=1200²；记录耗时与失败率
3. **人工盲评**：新引擎图与现有 SVG 保底图**混排盲评**，
   **胜出率 ≥70% 才允许替换默认**（防止"新是新的，但更差"）

## 14. 质量档实施方案

### 14.1 锁定组合

| 层 | 选定 | 理由 |
|---|---|---|
| 引擎 | **ComfyUI**（GPL-3.0，独立进程） | 实测活跃度第一（142k stars、2026-10-24 仍有提交、v0.42.1 本月发版），新模型支持最快 |
| 模型 | **FLUX.1-schnell**（Apache-2.0，12GB，1~4 步） | 许可最干净；蒸馏模型步数少、速度快；dev 版非商业 → 排除 |
| 后处理 | 1024² 原生 → LANCZOS 重采样到 **1200²**（1.17×） | 满足 §3 的方图与体积要求 |
| 兜底 | 现有代码生成 SVG（`/api/code-image`） | 引擎不可用时页面仍 100% 有图 |

**为什么没选 Qwen-Image**（虽然它中文最强）：本项目硬性要求"画面内不得出现文字"，
而它最强的能力恰恰是**文字渲染**——优势用不上；且 FP8 也要 ~16GB、模型体积更大。
列为"若将来要做带字海报再评估"。

### 14.2 部署拓扑

```
浏览器 ──► start-server.ps1 (8019) ──┬─► /api/code-image  （SVG 保底，毫秒级）
                                     └─► /api/ai-image ──转发──► t2i_server.py (8020)
                                                                  └─► ComfyUI (8188) ──► FLUX.1-schnell
```
- 三个进程**互相独立**：引擎 OOM 崩了，简报照常出（实测已验证自动回退）
- `t2i_server.py` 提供：队列（GPU 单并发）、缓存（同 id 不出第二张）、
  熔断（连续 3 次失败 → 跳闸 600s）、后处理（统一 1200² / 控体积）

## 15. B 方案落地清单（自购显卡）

### 15.1 先说清楚：这台笔记本**不能**加卡（实测结论）

| 实测项 | 结果 |
|---|---|
| 机型 | TIMI RedmiBook 14（笔记本，ChassisTypes=10） |
| 雷电 / USB4 控制器 | **未检测到**（只有 Intel USB 3.1） |
| 现有显卡 | Intel UHD(1GB) + NVIDIA MX250 **2GB** |
| 内存 | 7.8 GB |
| 项目所在盘 | `C:\Users\mi\CodeBuddy` 是指向 `D:\WorkFiles\CodeBuddy` 的链接 → 实际在 **D 盘，可用 327GB** |

**结论**：没有雷电/USB4 = 接不了显卡坞；笔记本也插不了桌面卡。
所以 B 方案在这台机器上的现实形态是 **另配一台机器**（台式机 / 工作站），
而不是"买张卡插到 RedmiBook 上"。

```
                    ↑ t2i_server.py 用 --comfy-url http://<新机器IP>:8188 指过去
```

### 15.2 硬件选型（**显存优先于算力**）

生图的瓶颈是"模型 + 文本编码器要常驻显存"，不是浮点性能，所以先看显存。

| 档位 | 型号举例 | 显存 | 功耗 / 供电 | 说明 |
|---|---|---|---|---|
| 下限 | RTX 3060 12GB | 12GB | ~170W / 单 8pin | 刚够 FLUX.1-schnell，后续大模型吃紧 |
| **推荐** | RTX 4060 Ti **16GB** | 16GB | ~165W / 单 8pin | 从容跑 schnell，还能上 Qwen-Image FP8；短卡、小电源、安静 |
| 大显存 | RTX 3090 24GB（多为二手） | 24GB | ~350W / 三 8pin | 升级空间最大；需大机箱 + 大电源 + 强散热，二手注意成色 |
| 不推荐 | 8GB 及以下 | — | — | 只能靠 GGUF 重度量化，画质与稳定性都打折 |

配套（容易被忽略、但装不上就白买）：

- **内存 ≥16GB**（建议 32GB）：模型加载与 CPU 卸载都要吃内存
- **磁盘 ≥100GB 可用**：FLUX.1-schnell fp16 权重约 24GB；GGUF 量化版可降到 8~12GB
- **电源**：按"显卡 TDP + 整机"再留 30% 余量 → 4060Ti 级别约 450W，3090 级别约 750W
- **机箱**：确认显卡**长度与厚度**（3090 多为三槽长卡），别买回来装不进去
- **价格**：以购买时行情为准 —— 本文档**不写未核实的价格**
